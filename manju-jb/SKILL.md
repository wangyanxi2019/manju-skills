# 漫剧分镜脚本

## 项目规则路径

先读取同级 `../manju-shared/PROJECT_RULES.md`。确定本作品的输出目录与作品名，运行该目录的 `resolve_project.py --work-dir 作品输出目录 --work-title 作品名`；仅在用户另指定规则项目时传 `--project`。使用返回的规则副本与本作品风格，避免跨作品套用风格。没有本技能专属参考文件时继续执行以下流程。

## 执行前确认视觉风格

**每次执行 `/manju-jb`，在编写本次分镜前先确认视觉风格。**运行 `python3 ../manju-shared/style_config.py --work-dir 作品输出目录 --title 作品名`，查看当前配置和从 `../manju-shared/references/漫剧生图影视风格预设.md` 读取的全部 13 个选项。首次使用时按 3D 动画、2D 动画、真人电影感分组展示名称和编号，并提供自定义选项；已有配置时先展示当前完整风格词，询问“沿用当前风格”或“更换风格”，更换时再展示全部选项。小说类型只能帮助推荐选项，不能代替用户选择。用户在当前请求中已明确写出风格、选定预设或说沿用本作品当前风格，视为本次确认；不重复询问。没有本次确认时，可继续阅读小说、整理事件与对白，但正式分镜不能生成，也不能把仓库里的修仙预设当默认值。

确认后用 `style_config.py --work-dir 作品输出目录 --title 作品名 --select 预设ID` 保存预设。自定义时从用户风格中整理通用、人物、无人场景和单物品四版，让用户一次确认，再用 `--custom-file 人物版文件 --base-file 通用版文件 --scene-file 场景版文件 --prop-file 物品版文件` 保存。旧版预设配置缺少变体而用户要求沿用时，可在本次确认后用 `--upgrade` 补齐，保留原人物风格词；旧版自定义配置则先审定变体。重新运行 `resolve_project.py --work-dir ... --work-title ...`，核对四版风格与 `style_file`。已有风格被更改时，标明此前受影响的分镜、人物、场景和道具稿需要按新风格重生成；不静默混用旧稿。配置文件与分镜输出放在同一作品目录，后续 RW/CJ/DJ 直接读取。

## H5 预览与交接数据

每次交付除原有 Markdown 文件外，再保存同名 `.json` 和 `.html`。Markdown 继续遵守本 Skill 原有的正式格式；JSON 采用同级 `../manju-shared/OUTPUT_FORMAT.md` 的结构。根 `data.global_style` 保存与 Markdown 顶部完全一致的全局风格及通用约束文本；`items[].prompts[].text` 只保存对应分镜组正文，不重复全局风格，且必须与 Markdown 中的该组正文一致。按该文档的 `data` 约定保留本 Skill 的结构化事实与来源，供后续 Skill 读取；不能用摘要替代完整镜头、台词、物品、人物或状态信息。若上游已有 JSON，先核对其组号、来源与原始文件，再复用已确认的字段。

保存 JSON 后运行 `python3 ../manju-shared/render_preview.py 输出文件.json`（从本 Skill 目录解析相对路径，或使用脚本绝对路径），生成同名离线 H5 `.html`。渲染器默认不改写 Markdown。逐项检查 HTML 条目数与 Markdown/JSON 一致、中文可读、手机宽度下不横向溢出，并实际点击一条 Prompt 的“复制”按钮验证复制正文。最后同时给用户 Markdown、JSON 和 HTML 的链接。


## 输入与阅读

1. 每次运行先完整读取项目解析结果中的 `references["manju-jb"]`（内置副本为 `references/分镜脚本.txt`）。该文件是用户可修改的项目规则，编辑后下次运行即生效。
2. 读取用户指定的小说原文和目标范围。若指定其中一集或一章，尽量通读其前后三章，以核对人物、代称、地点、道具、未完事件和后续回收。缺少相邻章节时继续处理，记录缺失范围。
3. 相邻章节只用于补足有原文依据的身份、外貌、场景和连续性事实，不把相邻章节的剧情、对白或动作搬进目标章节。对目标章节与上下文的矛盾，保留目标章节原文并在检查备注中指出。
4. 先建立事件顺序、原文对白清单、场景清单、人物和道具状态表，再分组。小说的心理、推断和叙述要么保留为有依据的 OS，要么转换成原文支持的可见反应。不要把叙述者的判断强塞给角色口述。

## 分镜编排

严格执行参考文件中的 15 秒、4—5 镜、单镜 1—5 秒、0.5 秒级时长、台词和空间连续规则。每组时长实际求和。以完整语义和动作节点分组，给有情绪的真人对白留出可说完的时间。若原文信息量与固定时长冲突，增加分镜组；不要加无意义镜头或删改台词来凑时长。

若单个完整句子以合理语速已超过15秒，“不拆句、不删改、严格15秒”无法同时满足，增加其他组也不能解决该句。将该句标为未解决时长冲突，在正式组之外保留原文并说明需放宽哪一条约束；继续完成其他可行段落，不把超时组标为已通过。没有实际音频文件时，VoiceID 写“未提供音频参考”，不伪造文件名。

每组写全场景、人物、物品、站位、摄影机侧和镜头轴线。只有原文或相邻章节明确支持的方位才写成事实。必要的创作性空间坐标应标为“为镜头连续性设定”，并在后续组保持一致。人物、房门、手中道具和家具的组末状态应与下一组起点一致。跳切按原文保留。

同一场景先建立一份可复用的固定空间地图：入口、可辨认的家具或地标、人物可走的路径、光源方向和行动轴线。每个相关分镜组沿用该地图，在镜头内分别交代人物相对地标的起点、运动路径、接触对象与落点；切镜后重新核对站位和视线。空间地图不改变参考文件的正式输出模板，也不把画幅左右当作空间方位。看不见的房间背面、门扇方向或精确距离标为未确认；已由分镜设定的坐标保持一致。

每镜只安排可在其时长内完成的主要动作。对开门、交接、坐下、吞药等关键动作，写清接触点、道具重量或惯性造成的可见变化，以及动作完成后的物品状态；没有原文或已确认设定支持的物理细节不写成事实。复杂动作装不下时拆成原文允许的相邻镜头，仍须满足每组 15 秒及台词完整性，不额外加入一秒广角或无意义铺垫。表演以有依据的目光、呼吸、停顿和动作反应表达；心理描写不能直接变成角色的新台词。

对白、OS、旁白和配音分别标明发声者、原文台词与镜头位置。每条 `【配音指令】` 必须紧跟该角色开始发声的 `【镜头】` 行；一组内有多人先后开口时，分别放在各自起声镜头下面，不能集中堆在本组所有镜头之后。若一句台词跨镜，指令仍放在起声镜头下，并写明覆盖镜头及声音衔接；需要逐镜分段时，各段分别紧跟对应镜头，按顺序拼接后必须与原句逐字一致。JSON 的 `shots[].dialogue[]` 归属起声镜头，跨镜时记录结束镜头 ID。若已有 `manju-rw` 人物声线卡，读取同一角色及造型／时期对应的固定音区、音色、语速、口音和说话习惯，只在本组的“状态／语气”中添加当前情绪、音量与停顿，不改动固定声线。记录角色稳定的声线卡 ID；实际提供的音频才填写对应文件路径，不能把文字声线卡当作已上传语音。跨组仍遵守“完整句不拆组”的参考规则。没有声线依据时标记待补，不从年龄、外表或性别推断确定音色。

读取本作品本次确认的 `style_base_prompt`：它优先替换参考文件中历史的“真人写实”等美术风格词，只在整份 Markdown 的标题下、第一组前完整写一次 `全局风格：`。另在顶部写一次 `全局摄影与声音约束：`，保留参考规则的焦段、景别、无字幕、无 SRT、无音乐等要求。分镜组内不设风格栏，不写“风格同上”，也不在每组末尾重复 `(no srt，no music)`；具体镜头仍写实际焦段、景别和表演。不要把仅适用于人物的五官、发丝或仅适用于某个环境的物件写成全局风格。角色台词必须逐字保留原文标点与顺序。出现原文疑似错字或矛盾时，原样保留并另列核对备注。

## 输出

输出一份 Markdown 文件，文件名包含作品名、章节或集数和“分镜脚本”。标题下先声明一次全局风格与通用摄影、声音约束，再按参考文件的正式模板逐组输出；组间使用单独一行 `@`。单组导出或单独投喂视频生成器时，先从文件顶部或 JSON `data.global_style` 读取通用约束并与该组正文组合，不把重复文本写回总脚本。文件末尾增加简短核对记录，列出目标章节覆盖范围、对白是否全部收录、每组时长与镜数检查结果、上下文补充来源、待用户确认的原文矛盾。聊天中提供文件链接。

输出前逐组审查原文事件与对白、秒数、动作接口、人物站位、摄影机轴线、道具状态和可读文字时长。未通过的组先修改。无法在原文依据下解决的冲突明确列在核对记录中，不宣称锁版。
