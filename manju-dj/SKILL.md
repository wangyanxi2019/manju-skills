# 漫剧关键物品设定

## 项目规则路径

先读取同级 `../manju-shared/PROJECT_RULES.md`，以分镜所属作品的输出目录和作品名运行 `resolve_project.py --work-dir 作品输出目录 --work-title 作品名`；用户另指定规则项目时才传 `--project`。使用返回的规则副本和作品配置，避免跨作品混用资产。没有本技能专属参考文件时继续执行以下流程。

## H5 预览与交接数据

每次交付除原有 Markdown 文件外，再保存同名 `.json` 和 `.html`。Markdown 继续遵守本 Skill 原有的正式格式；JSON 采用同级 `../manju-shared/OUTPUT_FORMAT.md` 的结构，`items[].prompts[].text` 必须与 Markdown 中对应的完整 Prompt 或分镜组正文一致。按该文档的 `data` 约定保留本 Skill 的结构化事实与来源，供后续 Skill 读取；不能用摘要替代完整镜头、台词、物品、人物或状态信息。若上游已有 JSON，先核对其组号、来源与原始文件，再复用已确认的字段。

保存 JSON 后运行 `python3 ../manju-shared/render_preview.py 输出文件.json`（从本 Skill 目录解析相对路径，或使用脚本绝对路径），生成同名离线 H5 `.html`。渲染器默认不改写 Markdown。逐项检查 HTML 条目数与 Markdown/JSON 一致、中文可读、手机宽度下不横向溢出，并实际点击一条 Prompt 的“复制”按钮验证复制正文。最后同时给用户 Markdown、JSON 和 HTML 的链接。


## 输入

读取用户提供的小说原文和分镜脚本，覆盖用户指定的章节或集数。分镜用于核对物品出场、持有和状态，小说原文用于核对名称、外观和变化。若两份材料有冲突，分别记录出处，保留原文事实，不擅自统一。

读取项目解析结果中的 `style_prop_prompt` 和 `style_file`，核对其属于本作品。单物品版与人物、场景版使用同一已确认的媒介和配色；每条物品图 Prompt 完整写入物品版风格词。若没有本作品配置，先按共用规则请求确认。旧版配置缺少物品版时先按共用规则补齐，不能把人物版或真人摄影质感当作默认风格。

## 提取与合并

逐章找出对剧情、动作、辨认角色或镜头连续性有作用的物品。包括武器、道具、装备、信物、法宝、药物、书信、容器和带有重要信息的物品。门、椅等普通陈设只有在其位置或状态影响剧情时才纳入。不要遗漏只出现一次却起关键作用的物品。

建立“原文称呼 → 统一物品名”的代称映射，并记录每项的章节或分镜出处。只有外观、所有权、状态和事件顺序均有充分依据时才合并代称。同类但不同个体的物品分开，例如两把尺寸不同的短剑。身份无法确认的物品保留独立条目并标记待确认，避免凭名称相似度误合并。

记录每个物品的首次出现、后续状态和具体版本。一个物品在剧情中明显改变外观或完整性时，保留统一身份，分别写状态版本的 Prompt。物品由容器与内容物组成时，根据它们在画面中是否独立出现，分别建立条目；单物品图一次只画其中一件。

对镜头连续性重要的物品，另列不含人名的状态接续表：每次出现时的位置、朝向、完整／损坏／开启／关闭／隐藏等实际状态、与环境接触的部位、下一镜可见的变化。确实出现的互斥状态分别建立版本，不把“藏在袖中”和“摆在桌面”同时画进一张单物品图。物理表现只记录可从材质、尺寸或原文动作支持的重量感、摆动、滑动和碰撞结果；无法判断的参数标为未说明。状态接续表供分镜使用，单物品 Prompt 仍只描绘当前这一件物品的外观。

## 外观字段与来源

每个物品必须列出外观、材质、颜色、尺寸和特殊标记。对每个字段标注“原文明确”“分镜明确”“视觉补全设定”或“未说明”。原文没有尺寸时，不得假装有准确数值；需要稳定生成时可给出明确标记的视觉估计。未记载特殊标记时写“未见明确记载”，不要虚构铭文、纹章或符号。对法宝等幻想物品，将文本描述转换成具有可信物理形体和表面质感的设计，不编造功能、发光效果或装饰。

物品的**描述和图像 Prompt 均不得包含人名**。也不要出现人物、手、持有者、身体部位或以角色身份间接指认物品。出处只写章节、段落或分镜编号，不引用含人名的原句。

## 输出 Markdown

输出一份 Markdown 文件，文件名包含作品名、范围和“关键物品设定”。文件按以下结构组织：

1. 关键物品索引表：统一物品名、已确认代称、类别、首次出处、版本或状态、身份疑点。
2. 每个物品的独立条目：原文与分镜依据、外观、材质、颜色、尺寸、特殊标记、状态变化，以及可直接复制的图片生成 Prompt。各字段明确区分事实、视觉补全和未说明。
3. 文件末尾列出未能确认的代称合并和来源矛盾。

图片生成 Prompt 以“真实物品，单物品图，白色背景”开头；这里的“真实物品”要求形体、结构和材质可信，不固定成照片媒介。随后写单件物品的形体、材质、颜色、尺寸比例、已有特殊标记和当前状态，并完整写入本作品的 `style_prop_prompt`。整件物品完整入画，主体居中，轮廓清晰，能看清关键表面细节。3D 动画采用三维资产渲染质感，2D 动画采用对应绘制质感，真人电影感采用真实摄影质感；不要在 2D 物品图中强加三维渲染或摄影词。不出现人物、手、场景、额外物品、文字说明、标签、拼贴或水印。原文写有物品上的文字时只保留该文字，不额外加入标题。不要把多个物品合成一张图，也不要用人物名描述来源。

## 输出前核对

核对指定范围内的关键物品全部进入索引；每个已确认代称只映射到正确物品；外观五字段齐全且来源标记准确；描述和 Prompt 不含人名；每条 Prompt 只有一个物品并明确白色背景。未通过时先修订，再交付 Markdown 文件链接。
