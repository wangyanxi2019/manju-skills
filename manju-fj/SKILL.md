# 漫剧四宫格分镜图 Prompt

## 项目规则路径

先读取同级 `../manju-shared/PROJECT_RULES.md`，运行该目录的 `resolve_project.py`；用户指定规则项目时传 `--project`。使用返回的项目路径、规则副本和风格文件，避免桌面可编辑文件与安装副本脱节。没有本技能专属参考文件时继续执行以下流程。

## H5 预览与交接数据

每次交付除原有 Markdown 文件外，再保存同名 `.json` 和 `.html`。Markdown 继续遵守本 Skill 原有的正式格式；JSON 采用同级 `../manju-shared/OUTPUT_FORMAT.md` 的结构，`items[].prompts[].text` 必须与 Markdown 中对应的完整 Prompt 或分镜组正文一致。按该文档的 `data` 约定保留本 Skill 的结构化事实与来源，供后续 Skill 读取；不能用摘要替代完整镜头、台词、物品、人物或状态信息。若上游已有 JSON，先核对其组号、来源与原始文件，再复用已确认的字段。

保存 JSON 后运行 `python3 ../manju-shared/render_preview.py 输出文件.json`（从本 Skill 目录解析相对路径，或使用脚本绝对路径），生成同名离线 H5 `.html`。渲染器默认不改写 Markdown。逐项检查 HTML 条目数与 Markdown/JSON 一致、中文可读、手机宽度下不横向溢出，并实际点击一条 Prompt 的“复制”按钮验证复制正文。最后同时给用户 Markdown、JSON 和 HTML 的链接。


## 输入范围

完整读取用户提供的分镜脚本，按组标题和 `@` 分隔符列出目标范围内的所有15秒组。默认处理整份脚本；只有用户明确指定部分组号时才缩小范围。每组提取场景、人物、固定物、初末状态、4—5个镜头、原时长、摄影机侧和道具变化。逐组产生一条四宫格绘图 Prompt，不能只做首组或样例。

按用户拟上传或已上传的图片顺序，为本组入镜人物、场景和关键道具分配 `@图一`、`@图二` 等编号。即使图片尚未在当前聊天出现，也在 Prompt 内保留 `@图N是……参考图` 的上传占位句，并在 Prompt 外说明哪些图尚待上传。人物及场景外观由参考图锁定。图片没有覆盖的区域不能冒充已核验。

在 Prompt 外的对应表中登记每张参考图的实际作用：人物身份与造型、场景已见布局、物品当前外观，或仅作为四格构图依据；记录实际已上传／拟上传状态和与上游人物、物品、场景版本的对应关系。Prompt 内第二部分仍只保留简短 `@图N是……参考图` 行。参考图若与分镜的构图或空间事实冲突，指出冲突并按已确认分镜选帧，不把参考图的错误位置复制到下一格。

## 每组绘图 Prompt 的固定格式

**严格按1→2→3→4→5顺序写。**每部分在同一个可复制代码块内，部分间留空行。不要插入额外的风格段落、分镜时长表或人物外貌段落。

1. 固定首句，逐字写 `生成一张横向2×2四宫格分镜图，依次表现同一段故事的四个关键瞬间。`
2. 参考图映射，紧接首句，每张图独立一行，只写 `@图N是［人物姓名］形象参考图`、`@图N是［场景名］场景参考图` 或 `@图N是［物品名］参考图`。用实际姓名和场景名，不用“年长男子”“少年”等泛称。映射行不加用途、括注、状态或说明。
3. `故事概况：` 一两句，只归纳本组分镜的起点、主要变化和落点。保留人物姓名、事件顺序与因果，不从小说或其他组补桥段。
4. `固定空间关系：` 锁定门、桌、椅、道路等已有固定物的场景方位，再写每个人物相对于这些物体的起始站位、面朝方向、路径和最终站位，以及摄影机处在行动轴线哪一侧。同一场景跨组沿用同一坐标。没有依据的方位或精确距离不要捏造。这里的“占位”是人物在场景中的**物理位置**，不是画幅中的左右或占画比例。
5. 依次写 `左上：`、`右上：`、`左下：`、`右下：` 四段，最后写统一约束。每格呈现对应镜头的一个静态瞬间，说明人物相对固定物的位置、朝向、动作状态、门和道具状态。上一格的终点接到下一格起点，最后一格达到本组结尾状态。统一约束写人物外貌和场景结构以参考图为准、固定物不换位、状态连续、无额外人物及无文字字幕水印。

每条 Prompt **不输出**“东方水墨修仙3D国漫……”等项目风格长串，也不设“风格：”栏。人物与场景图已经提供视觉依据，绘图 Prompt 只写画面、空间和连续性。参考图风格冲突时，在 Prompt 外指出具体冲突。不要把“人物和场景参考图为准”改写成长段视觉风格。声音和对白只供选帧，不画声波、音效字或对白气泡。

## 分镜与图片的关系

四镜组一镜对应一格。不要在一格中画同一人物的多个动作阶段、分身、残影或运动轨迹。五镜组仍须覆盖：选四个关键静态瞬间，另在 Prompt 外记录未单独成格的镜头；若用户要求五镜逐镜都有图，再增加第二张四宫格 Prompt，并注明它的辅助格，不添加新剧情。在 JSON 的 `data.grids[].panel_map` 保存四格到原分镜 `shot_id` 的明确对应，在 Markdown 对应表也列出同一映射。例如五镜选第1、2、4、5镜时，左下对应 Shot 4，不能被下游默认当作 Shot 3。`uncovered_shot_ids` 记录未单独成格者；静态图没有覆盖的镜头仍保留在原视频时间线上。辅助四宫格分别有唯一 ID，沿用同一 `group_id`，不能作为新故事组计数。

选帧前逐镜核对人物从哪里来、目光指向哪里、手中物品和门窗处于什么状态，优先选择能看清关键变化的静态瞬间。四格相邻状态要能由原分镜动作自然连接；若原分镜有明确跳切，则保留跳切并在 Prompt 外记录，不硬造连续动作。静态图不画音色、对白或声音文字；声音只用于判断角色何时转头、停手等可见反应。不强制加入“首秒广角”，也不把电影示例的真人风格放进这条图片 Prompt。

时长只写在 Prompt 外的组号与镜头对应表中，静态图代码块内不写 `0–3秒` 或 `约3秒`。

## Markdown 交付

输出包含全部目标组号的 Markdown 文件。每组给组号、镜头与时段对应表，以及按五部分格式写出的独立代码块。文件开头列组数，末尾列漏图或分镜矛盾。输出长时可按集拆文件，但必须提供全量索引。

## 最终检查

逐组按 **1、2、3、4、5** 检查，不合格先修订。

1. 首句是否与固定句完全一致。
2. `@图N是……参考图` 是否紧随首句、逐图单行、编号有序，覆盖本组实际需要的人物与场景。
3. 故事概况是否忠于该组分镜，写清起点、变化和落点。
4. 固定空间关系是否说明固定物、人物物理站位、方向、路径和轴线，跨组坐标是否一致。
5. 四格是否齐全且顺序正确，人物和道具是否不跳位，门等状态是否连续，统一约束是否齐全。

再核对输入组号与输出唯一 `group_id` 集合一致（默认每组一条 Prompt；用户要求的辅助图单列，不作为漏组或新组）、每组原时长已在代码块外检查、代码块无长风格词、无人名被泛称替换、无画面占比式“占位”、无多余人物和画面文字。
