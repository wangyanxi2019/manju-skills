# 漫剧人物与三视图

## 项目规则路径

先读取同级 `../manju-shared/PROJECT_RULES.md`，以分镜所属作品的输出目录和作品名运行 `resolve_project.py --work-dir 作品输出目录 --work-title 作品名`；用户另指定规则项目时才传 `--project`。使用返回的规则副本与本作品风格。没有本技能专属参考文件时继续执行以下流程。

## H5 预览与交接数据

每次交付除原有 Markdown 文件外，再保存同名 `.json` 和 `.html`。Markdown 继续遵守本 Skill 原有的正式格式；JSON 采用同级 `../manju-shared/OUTPUT_FORMAT.md` 的结构，`items[].prompts[].text` 必须与 Markdown 中对应的完整 Prompt 或分镜组正文一致。按该文档的 `data` 约定保留本 Skill 的结构化事实与来源，供后续 Skill 读取；不能用摘要替代完整镜头、台词、物品、人物或状态信息。若上游已有 JSON，先核对其组号、来源与原始文件，再复用已确认的字段。

保存 JSON 后运行 `python3 ../manju-shared/render_preview.py 输出文件.json`（从本 Skill 目录解析相对路径，或使用脚本绝对路径），生成同名离线 H5 `.html`。渲染器默认不改写 Markdown。逐项检查 HTML 条目数与 Markdown/JSON 一致、中文可读、手机宽度下不横向溢出，并实际点击一条 Prompt 的“复制”按钮验证复制正文。最后同时给用户 Markdown、JSON 和 HTML 的链接。


## 输入与核对

1. 每次运行读取项目解析结果中的 `references["manju-rw"]`（内置副本为 `references/人物三视图例子.txt`），采用左侧完整头部特写、右侧正面／侧面／背面颈根以下至鞋底视图的布局。示例中的具体人物、官职、身高和服装只属于示例人物，不套用到其他角色。
2. 完整读取用户提供的小说原文和分镜脚本。逐章提取实际登场者、被提及者、回忆中人物、群体和身份未明者。建立“原文写法 → 规范人物名”的代称表，记录首次出处。仅在同一人物有足够文本依据时合并代称，不确定则单列并标记待确认。群体未有个体身份时作为群体条目，不凭空拆成多人。
3. 以小说原文为事实来源，分镜为镜头出场和造型状态来源。若两者矛盾，保留两个说法并标明出处，不悄悄选择其一。

## 角色设定

每个条目必须给出年龄、性别、发色、发型、眼睛颜色、上身服装、下身服装。原文未说明的字段标注“视觉补全设定”，给出适合统一生成的具体值，不能将其冒充小说事实。年龄若只有阶段信息，用“约 X 岁”作为视觉补全设定；原文年龄范围优先保留。性别不明时不要用确定性描述，可写“未明确；视觉补全设定为…”。

为每个不同角色指定可辨认的着装组合，包括上衣结构或颜色、下装结构或颜色、关键配件。先遵守原文服饰，再通过未被原文固定的细节区分。不得为了区分人物而改变原文明示的服装。角色若跨章节换装，分别记录造型版本，并说明出现范围。不要给未知人物编造背景、身份、性格或剧情动机。

## 人物声线卡

为每位实际有对白、OS、旁白或演唱的人物另建一份可独立复用的声线卡；仅被提及或始终不发声的人物标明“本范围无发声”，不捏造音频或 VoiceID。声线卡记录规范人物 ID、稳定声线卡 ID、音区、音色／共鸣质地、呼吸感、常态语速、口音或发音习惯、句尾／停顿习惯、适用章节和来源。已提供的语音参考记录实际文件路径及对应角色；未提供时写“无音频参考”，文字声线是生成约束，不能宣称已锁定真实音频身份。原文明确、用户指定、参考音频可听和声音补全设定逐项标注，不凭外貌、性别、地域或年龄臆断口音与音色。

同一角色跨集沿用同一段固定声线描述，逐字复用；仅在原文、剧情状态或用户素材明确改变声线时建立有范围标记的新版本。将固定声线与每场的情绪、音量、语速变化分开记录：人物可以因紧张而说得更快，底层音区与咬字习惯仍可追踪。对有实际音频的角色，抽查不同句子和情绪下是否仍可辨认为同一声音；有漂移先核对音频、角色映射和声线描述，不用强行添加原文没有的口音。生成模型的文字描述不能保证跨镜完全同音，必要时在配音或后期环节使用经用户确认的同一语音参考。

声音卡放在人物资料和 JSON 的 `data.characters[].voice_profile`。每位发声角色另给一条可独立复制的“固定声线描述 Prompt”，只写确认的角色声线与明确标为声音补全的设定，不掺入当前场景情绪，不冒充已上传音频；HTML 中作为第三条可复制 Prompt 展示。它不塞进两条图片生成 Prompt，也不改变人物三视图的裁切、背景和已确认视觉风格。人物图继续使用稳定的视觉描述；实际出现的换装、受伤、沾水等状态按原文分版本记录，不能把互斥状态合成一个默认造型。

## 共用视觉风格

开始生成人物图片 Prompt 之前，读取项目解析结果中的 `style_prompt` 和 `style_file`，核对其属于本作品。将完整风格词逐字写入**每一条**人物图片生成 Prompt，包括人物形象和人物三视图。不能只在文件开头写一次，也不能改写或缩写风格词。

若没有本作品配置，先用 `style_config.py` 展示候选风格并请求确认，再保存到本作品的 `视觉风格配置.json`，然后生成正式 Prompt。用户在当前请求中明确给出并指定风格时，视为本次已确认。若用户明确更换风格，更新本作品配置并标明受影响的 Prompt 需要重新生成。示例文件的风格只用于形成候选，不覆盖用户确认的本作品风格。人物设定板的白色背景不用于剧情场景。

## 人物 Prompt 的风格位置

每位人物必须分别输出两条可独立复制的 Prompt：`人物形象生成 Prompt` 和 `人物三视图生成 Prompt`。两条 Prompt **各自完整包含**项目风格词。人物形象 Prompt 在人物年龄、性别、发色、发型、眼睛颜色、上衣和下装等具体描述后，直接写入完整风格词；不能只在三视图 Prompt、文件风格栏或索引中写一次。三视图 Prompt 也独立写入同一整段风格词。生成后逐条检查两个代码块都含有完整风格词。

## 输出 Markdown

输出一份 Markdown 文件，包含：

1. 人物索引表。列出规范名、所有已确认代称、出现类型、首次出处、造型版本和不确定身份。
2. 每个角色的原文依据与视觉补全字段，分别写出人物形象生成 Prompt 和三视图生成 Prompt；有发声者另列人物声线卡与固定声线描述 Prompt。图片 Prompt 为可直接复制的完整文本，明确写入共用视觉风格，逐一包含年龄、性别、发色、发型、眼睛颜色、上身和下身服装。声线 Prompt 是额外一条，不改变两条图片 Prompt 的要求。
3. 三视图 Prompt 沿用示例的背景规则（通常纯白；白色服装用浅灰以保留轮廓）、左侧约半幅面部主视觉、右侧正面／侧面／背面三幅从颈部以下至鞋底的身体与服装视图。右侧三幅统一比例和地面基线，在颈根处整齐裁切，不绘制头、脸、头发、耳朵、五官或发型细节，也不留头部轮廓或空白占位。左侧主视觉独立展示完整头部、发型和清晰五官。四幅均对应同一个角色及同一套服饰，右侧重点展示领口以下的衣物结构、肩线、袖型、腰带、下装和鞋。不要再写“右侧头顶完整”“侧面展示发髻”“背面展示束发”等与颈部裁切相冲突的描述。示例要求的“178cm”和“高跟鞋”只在该角色原文或用户指示支持时使用。
4. 文件末尾列出未解决的代称、外貌或服饰冲突，以及全部角色覆盖检查。

生成前核对原文中的每个称谓都已映射到一个角色或明确标记待确认。检查各人物着装能区分、每份 Prompt 字段完整、同一角色的正侧背描述互相一致。聊天中提供文件链接。
