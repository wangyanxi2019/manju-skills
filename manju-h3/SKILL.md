# 漫剧 MiniMax H3 视频提示词

## 项目规则路径

先读取同级 `../manju-shared/PROJECT_RULES.md`，以分镜所属作品的输出目录和作品名运行 `resolve_project.py --work-dir 作品输出目录 --work-title 作品名`；用户另指定规则项目时才传 `--project`。使用返回的规则副本和作品配置，避免跨作品混用参考素材。没有本技能专属参考文件时继续执行以下流程。

## H5 预览与交接数据

每次交付除原有 Markdown 文件外，再保存同名 `.json` 和 `.html`。Markdown 继续遵守本 Skill 原有的正式格式；JSON 采用同级 `../manju-shared/OUTPUT_FORMAT.md` 的结构，`items[].prompts[].text` 必须与 Markdown 中对应的完整 Prompt 或分镜组正文一致。按该文档的 `data` 约定保留本 Skill 的结构化事实与来源，供后续 Skill 读取；不能用摘要替代完整镜头、台词、物品、人物或状态信息。若上游已有 JSON，先核对其组号、来源与原始文件，再复用已确认的字段。

保存 JSON 后运行 `python3 ../manju-shared/render_preview.py 输出文件.json`（从本 Skill 目录解析相对路径，或使用脚本绝对路径），生成同名离线 H5 `.html`。渲染器默认不改写 Markdown。逐项检查 HTML 条目数与 Markdown/JSON 一致、中文可读、手机宽度下不横向溢出，并实际点击一条 Prompt 的“复制”按钮验证复制正文。最后同时给用户 Markdown、JSON 和 HTML 的链接。


## 首先读取项目规则

每次运行先完整读取项目解析结果中的 `references["manju-h3"]`（内置副本为 `references/视频大师提示词.txt`），它是用户可修改的原始提示词副本；修改后下次运行生效。该文件规定中文说明正文、六字段顺序、参考标签、分镜切点和声音写法。官方格式参考的来源见 `references/official/SOURCE.md`：本地若有 `ref-en.txt` 和 `base-en.txt` 可直接读取；公开仓库未附全文时，通过该说明中的官方链接核对最新格式，无法访问时标明官方资料未核验。官方要求英文说明正文；本项目按用户明确要求使用中文，这是有意的中文适配，不称为完全符合官方英文输出。固定字段、标签、关系标记和切镜语法仍按官方。

本 Skill 补足输入核对、批量处理和一致性检查。用户当前请求的明确指示优先于文件中的通用规则。

## 输入与组号配对

**文字分镜脚本是每条 H3 提示词的必读输入。**先完整读取用户指定的分镜脚本文件，并定位目标组号；整份脚本的风格与通用摄影、声音约束优先从文件顶部或同名 JSON 的 `data.global_style` 读取，不能因为单组正文没有风格栏就套用默认风格。没有对应分镜正文时，不仅凭四宫格图片写正式 H3 提示词。逐组抄取并核对 `场景`、`人物`、`物品`、`站位`、各镜景别与焦段、每镜时长、动作、对白、音效和结尾状态。若用户只贴出一组正文，就以该组为范围；若提供整份脚本，默认处理整份。四宫格及人物、场景参考图用来核对可见画面，不能替代分镜中的时长、动作和声音。

读取用户提供的全部目标文字分镜组和实际上传的素材。默认处理用户提供范围内的所有分镜组；只在用户明确指定组号时缩小。先列出组号、镜头数、总时长、每镜时长与累计切点。将每张四宫格图片按组号与一组分镜配对；先读取上游 FJ 的 `data.grids[].panel_map`，再与实际图像核对。仅在四镜且顺序匹配时，才使用左上、右上、左下、右下对应 Shot 1—4 的默认规则。五镜或辅助图必须按明确映射配对，例如四格可能对应 Shot 1、2、4、5；不按格序重编号视频镜头。未成格的镜头仍按文字分镜保留时长和内容，只使用确有依据的人物／场景参考，并注明没有独立格图；映射无法判定时将该组标为待配对，不交付含猜测映射的正式提示词。此规则优先于原始提示词中默认四镜的示例。未能配对的组列出缺少的素材，不编造图像内容。

建立实际上传素材清单，明确哪张是人物形象图、哪张是场景图、哪张是道具图、哪张是四宫格分镜图，语音文件对应哪位说话者。只对真实素材赋予 `<Picture N>`、`<Subject N>`、`<Audio N>` 等标签。同一张四宫格图片是**一项**图片素材，四个分格是这项素材的四个区域；不能把四格虚构为四张单独上传的 `<Picture N>`。后续所有字段沿用同一标签和角色身份。

读取上游 `manju-rw` 的人物声线卡和 `manju-jb` 的发声者记录，按规范人物 ID、声线卡 ID、造型／时期版本与组号配对。固定声线描述优先使用用户确认的声音设定与实际语音参考，来源不足时沿用明确标为“声音补全设定”的版本；没有声线卡时在 Prompt 外列待补项，不能从人物外观或性别推断确定音色。文字声线描述只是一种生成约束，不是音频文件；只有实际上传且匹配该角色的声音素材才能赋予 `<Audio N>`。若上传音频与声线卡冲突，列明冲突和采用依据，不把两套不同音色拼接成同一个角色。

文字分镜决定事件、动作顺序、台词、音效、时长和人物位置。参考图决定可见外观、构图、场景固定物、光线和可见道具。逐镜核对图文差异；若冲突会改变剧情或空间连续性，在最终 Prompt 外记录冲突，按用户明确确认的分镜信息编写，不能凭图新增剧情。未提供的图片、音频、角色外貌或场景背面不能写成已经核验。

## H3 编写

根据 `视频大师提示词.txt`，参考图任务使用 Ref2VA 的六字段结构，字段名和顺序固定如下。每组分镜输出一条独立、可复制的视频提示词。

```text
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

六字段的说明正文按用户规则写中文；标签、字段名、`[Shot N]`、时间切点和 `<d>[Chinese]…</d>` 保持规定的英文形式。原台词、歌词和画面文字逐字保留原语言与标点。`subject_definitions` 说明各素材的身份和参考作用，包括四宫格作为分镜构图参考。`summary` 以实际任务类型开头，如 `[reference generation]`；使用音频参考或复用时依官方增加相应类型。`retention_analysis` 每个已定义参考标签一行：可见内容使用 `fully_preserved`、`partially_preserved`、`attribute_transfer` 或 `weak_reference`；音频使用 `fully_copy`、`partially_copy`、`reference` 或 `weak_reference`。随后用中文说明在既定参考作用内如何保留，不引入未定义标签。仅定义人物外观的图片在 `<Subject N>` 中注明来源；有首帧、关键帧或分镜构图作用时才建立独立 `<Picture N>` 条目。

声线卡不新增第七字段，也不独立伪造参考标签。说话角色若有 `<Subject N>`，在其定义或首次发声处说明固定声线；实际 `<Audio N>` 按已上传文件写明是复制音频还是只参考音色，再在 `retention_analysis` 使用对应的音频关系标记。没有实际语音素材时，`summary` 不声明 `audio reuse` 或 `audio reference`。同一角色跨分镜组沿用声线卡 ID 和固定声线描述；`(S1)` 等编号按每条目标视频中的实际发声顺序分配，并在该条视频内稳定，不把编号误当成跨文件的角色身份。

`detailed_description` 在 `[Shot 1]` 前用一两句中文建立参考素材已确认的视觉风格，不添加新的风格词。随后沿播放顺序逐镜描写可见画面、动作发展、人物相对门窗桌椅的物理位置、道具状态、摄影机位置与运动、声音发生点。Shot 1 不写起始时间；之后每次切镜写准确切点，如 `[Shot 2] At 00:04.000, the camera cuts to...`。切点由前镜时长实际累加，末镜在指定总时长结束。保持摄影机轴线、室内外方向和人物、道具位置连续，镜头转场只按原分镜写。每镜写四宫格的对应区域；若参考图没有覆盖该镜，不能声称存在相应区域。

有对白、OS、旁白或演唱时给实际发声者按首次发声顺序分配稳定 `(S1)`、`(S2)` 等 ID，在 `<d>[Chinese]原台词</d>` 内逐字保留台词。角色 OS 使用官方固定短语 `says in an off-screen voiceover`，紧跟每个 `<d>` 后注明画面中该角色嘴唇闭合；纯旁白没有对应画内人物时，不凭空增加人物。电话声及其他画外音按实际来源写清，不将未说话角色做成口型。同一句对白跨镜时在前后两部分连接处使用 `<scenetrans>` 并写清声音连续；拼回后必须与原台词完全一致。仅在原分镜明确声音被视频结尾截断时用 `<cutoff>`，不能用它掩盖台词超时。没有上述人声内容时不创建发声者 ID。`overall_soundscape` 只概括环境声和动作音，不重复对白；没有配乐时写 `non_diegetic_music: N/A`。无普通对白字幕、无 SRT；剧情本身存在的文字照原分镜保留。

在每位角色的首次发声处写固定音区、音色／共鸣、呼吸感、常态语速、口音或发音习惯及声线卡 ID；这些内容放在 `<d>` 外，后续发声保持同一身份。当前镜头的情绪、音量、停顿可随分镜变化，但不把它们误写成新的底层声线。逐镜说明谁开口、谁保持安静、对白何时开始或跨镜继续；未获原文支持时不额外添加语气词、笑声或新台词。对白与环境声的相对关系可写在对应镜头，环境声保持可追踪；不为了衔接而重复原分镜没有的上一句台词。若句子跨镜，核对两个 `<d>` 片段拼回后的原文、说话者、声线和切点。声线只靠文字提示无法保证完全同音，实际输出仍需听检；需要精确复用时以用户确认的真实音频为依据。

镜头描述只写原文、分镜与参考素材支持的内容。可用具体摄影机运动提升可执行性，但不增加剧情动作、角色动机、服装、光色、道具、转场或场景结构。若用户要求电影级质感，以参考图的视觉风格与分镜的摄影参数表达，不覆盖已确认素材。

## Markdown 交付与检查

输出 Markdown 文件，按原组号顺序每组给出素材对应关系、时间切点核对、一个六字段 H3 提示词代码块，以及必要的图文冲突备注。文件开头列输入组数和输出组数；可按集拆文件，但必须覆盖全部目标组。聊天中提供文件链接。

逐组检查：素材与组号真实配对；四宫格区域与 Shot 对应；参考标签在六字段中定义且意义一致；六字段名称与顺序准确；说明正文用中文；所有原台词未删改；切点递增且末镜时长准确；人物、空间、门、道具和声音连续；同一角色跨组声线卡一致、情绪变化不重写固定音色、实际音频与 `<Audio N>` 一一对应、无台词角色不乱发声；无虚构素材、普通对白字幕或未授权音乐。发现不满足的组先修订，无法核实的素材缺口在代码块外如实说明。

在提交前将输出与对应的**分镜脚本原组**逐镜对照，确认每个 Shot 的景别、动作、时长和音效都有出处。例如原组为 `4秒＋3.5秒＋3.5秒＋4秒`，应得切点 `00:04.000`、`00:07.500`、`00:11.000`，整段在 `00:15.000` 结束；不能从四宫格的四个静态画面猜测时长。
